# Luna Explicit-Cache Trial: 100 Worlds

## Protocol

- Trial: `top20_luna100_cached_20260907`.
- Comparator: `top20_luna100_20260907`; do not modify its completed artifacts.
- Same 20 reference sources and five matched tasks per reference, seeds
  2026091800-2026091804. All 20 fresh reference preflights passed.
- Generator: `gpt-5.6-luna`, Flex, reasoning `none`, source output, 32,000-token
  cap, 900-second request timeout, concurrency limit 50.
- Fixed prompt block has an explicit cache breakpoint; task fields are a second
  block in the same user message. Explicit-only mode, 30-minute cache TTL, same
  stable per-reference keys as the comparator. No prompt addendum.
- All 100 concatenated prompt texts match the comparator after normalizing
  target paths. Other generation fields match except the cache settings.
- Finish one real generation per reference before releasing its remaining jobs.
  First run the five Garnet jobs as a live cache check, then resume the same
  frozen trial for the remaining 95. No extra paid warm-up requests.
- Existing general repair plus import-only repair, four local workers, 1,000
  requested samples per world, verification, standalone and deterministic replay.
  One additional manual loop bound fixes a timeout discovered at 1,000 samples;
  its original failing audit and source are retained separately.
- No paid judge or quality estimates. Local validation is not story/QA quality.
- Preserve frozen requests, usage, attempt/response ledgers, raw/repaired source,
  compressed sample pools, checks, runtime snapshots, and a checksummed archive.

## Commands

Preparation used the explicit-cache command in `QUALITY_ITERATION_PIPELINE.md`,
then added `local_workers=4`, `compress_samples=true`, `compact_checks=true`,
`skip_quality=true`, and `large_batch_protocol="reference_batch_v1"` to the
new trial config. No completed batch configuration was changed.

```bash
OPENAI_API_KEY="$(cat .API_KEY)" OPENAI_BASE_URL=https://api.openai.com/v1 \
  caffeinate -is ./.venv/bin/python storyworlds/large_world_batch.py generate top20_luna100_cached_20260907

caffeinate -is ./.venv/bin/python storyworlds/large_world_batch.py audit top20_luna100_cached_20260907
```

The five-job pilot used `prompt_trials.generate` with the first arm only, under
the same trial lock and durable ledgers. The normal generation command resumes
without charging for those completed jobs again.

## Results

All 100 generation responses completed and were materialized. Every response
reported `gpt-5.6-luna` and `flex`. No API errors were recorded. No quality judge
was called; quality, semantic diversity, and the composite score are unmeasured.

| Output tokens | 479,395 | 471,926 |

| Total generation cost | $0.406184 | $0.315223 |

Every reference had exactly one cold write and four cache-reading follow-ups.
All 80 follow-ups reused the complete marked prefix and wrote zero cache tokens.
The whole-run cache-hit fraction includes the 20 cold starts; among warmed
requests, about 98.8% of input tokens were cached. The Garnet pilot alone wrote
9,640 prefix tokens once and read those same 9,640 tokens on each follow-up.

Input spending fell **72.95%**. Total generation spending fell **22.39%**, partly
because this stochastic run also generated 7,469 fewer output tokens. These are
returned-usage estimates, not invoice reconciliation or a guarantee about
transport retries. Flex rates per million tokens are $0.10 ordinary input,
$0.01 cache reads, $0.125 cache writes, and $0.60 output. The frozen prompt text
is matched, but splitting content blocks and changing target paths resulted in
100 additional input tokens across this run.

Detailed evidence: `cache_pilot.json`, `cache_usage.json` (including per-reference
counts), `cache_comparison.json`, and the original per-arm response ledgers.

Repair categories overlap and must not be summed as distinct recovered worlds.
83,080 sample rows are retained in compressed per-world pools. Underfilled
worlds are not padded. Source hashes and sample counts match the final audit
records for all 100 worlds, and raw sources remain available.

The general repair script was not changed. Three of its four accepted repairs
include `downgrade_storyerror_raises`; runnable status therefore does not prove
that original semantic guards, story quality, or QA correctness are preserved.
Import repairs require unchanged existing sample pools and do not relax a
previously passing verifier.

The timeout was `repaired_060/terminate_grizzly_scour_inner_monologue_quest_happy.py`.
Its unbounded unique-story loop passed ten samples but timed out at 1,000.
The manual patch caps attempts at `max(1000, 20 * requested)` and reports a
shortfall on stderr. It now returns 336 unique stories, passes verification and
deterministic replay, and preserves the original first ten samples exactly.
It still fails the full-count gate. No story padding or new random draws were
introduced before the bound. Original timeout evidence lives under
`qc/manual_repair_baselines/`; the plan/result JSON records the patch separately.

The remaining ten runtime failures are nine syntax errors and one undefined
`bacon` variable. Their paths and errors are listed in `repair_summary.json`.
No manual content fixes or paid repair calls were used for those failures.
